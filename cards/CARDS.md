## c15 循环病理（4 件）— 证据：`agent loop deadlock` 全 GitHub 仅 11 仓、对口仅 2 个且互为复制品

- **L56 活锁熵检**：L0 它看 agent 是不是在"忙但没进展"——一直在动，却总在同一圈里打转。L1 对连续 N 步动作序列算重复度（归一化编辑距离/集合熵），重复度超阈且无新事实产生 → 判活锁。L2 边界：只看动作签名，不看语义；断言=①对 `[A,B,A,B,A,B]` 判活锁、②对带新产物的 `[A,B,C]` 判正常。
- **L57 死锁等待图**：L0 多个伙伴互相等对方先动，谁都动不了——它把"谁在等谁"画出来，发现成环就叫醒你。L1 从各 agent 状态采集等待关系（waiting_on），建有向图，DFS 找环，有环 → 死锁。L2 断言=①A等B、B等A 判死锁、②A等B、B在跑 不判。
- **L58 振荡翻转检测**：L0 它抓"翻烧饼"：结论在两个说法之间来回横跳，每轮都推翻上一轮。L1 对判定/结论序列找长度 ≤k 的周期性重复子串（如 A,B,A,B），命中 → 振荡。L2 与 L56 区别：L56 看动作重复，本件看**结论翻转**；断言=①`[x,y,x,y,x]` 判振荡、②`[x,x,x,y]` 不判。
- **L59 循环预算熔断**：L0 给"原地打转"设一个硬性花费上限，到线就强制停，不许再烧。L1 记录无新信息步数与累计花费，任一超阈 → 返回 HALT 信号。L2 断言=①5 步无新信息且花费超阈返回 HALT、②有新信息时不返回。

## c16 采样与分诊（4 件）— 证据：`temperature policy llm` 放宽复查后对口≈0（真空白）；HN：评测成本已达 agent 本体 5 倍（Tessary，1M traces 案例）

- **L60 每步档位策略**：L0 不是每一步都值得动用最大火力——它按步骤的难度和风险决定用多聪明的模型、想多深。L1 输入步骤特征（可逆性/影响面/历史失败率），输出档位（cheap/balanced/max），纯规则可解释。L2 断言=①可逆+低影响 → cheap、②不可逆+高影响 → max。
- **L61 廉价预筛**：L0 先用便宜的办法把 1000 份记录扫一遍，只把可疑的几份交给贵的仔细看——像保安先瞄一眼再决定要不要开包。L1 L1 分类器（关键词/规则/小模型）全量扫，只放行可疑子集给 L2 深审；输出召回率下界估计。L2 断言=①可疑集非空时通过、②规则表为空时显式报「无法分诊」而非放行全部。
- **L62 深挖配额**：L0 仔细看一份记录很贵，所以一天只许深挖固定几份，超过就得先说理由。L1 记录深挖次数与预算，超配额则要求附「为什么这份值得」字段，缺字段拒绝。L2 断言=①超配额+无理由 → 拒、②超配额+有理由 → 过。
- **L63 评测成本比**：L0 盯一个比值：检查作业花掉的钱 ÷ 干正事花掉的钱。检查比干活还贵 5 倍，就该换检查方式了。L1 输入两侧花费，算比值，超阈报警并给三条降本路径。L2 断言=①5.0 倍报警、②0.5 倍不报。

## c17 幂等与重放（4 件）— 证据：`tool call idempotency` 全 GitHub 仅 46 仓且 star 全为 0（萌芽期，窗口最开）

- **L64 幂等键**：L0 同一件事不许干两遍：重试前先带上"这件事的编号"，对方一看编号干过就直接回上次的 结果。L1 为每个有副作用的调用生成稳定键（目标+参数哈希），重试时先查已执行登记。L2 断言=①同键二次调用不重复执行、②不同键正常执行。
- **L65 恰好一次写**：L0 写文件的活要保证"要么写成功一次，要么明确失败"，绝不写一半没人管。L1 写前登记意图→写入临时区→校验→原子提交→销毁登记；中断恢复时按登记补完或回退。L2 断言=①模拟中断后恢复时完成提交、②无登记的孤儿临时文件被识别。
- **L66 重放等价**：L0 把同一段操作重跑一遍，结果应该一样；不一样说明有东西在暗地里变了。L1 记录首次执行的输入/输出指纹，重放比对，不一致输出差异定位。L2 断言=①纯函数重放一致判 PASS、②含随机数未固定种子判 FAIL 并指出。
- **L67 副作用清单前置**：L0 动手之前先列"这步会动到哪些东西"——文件、网络、钱、别人。没清单不许执行。L1 执行前强制产出副作用清单（对象/可逆性/影响面），清单缺失或含未声明副作用 → 拦。L2 断言=①无清单拦截、②清单含「不可逆」项时要求二次确认标记。

## c18 断点与恢复（4 件）— 证据：`agent checkpoint resume` 225 仓半满但对口少；HN 亲测痛点：checkpoint 缺意图与计划，冷启动恢复不了；NVIDIA flare：分支后状态完整性

- **L68 冷启动恢复测试**：L0 检查"存档"够不够新来的人用：只看存档，一个全新的伙伴能不能接上活？接不上就是坏存档。L1 用空白上下文只读 checkpoint 尝试复述：目标/已完成/下一步/约束，四项复述不出 → 判存档不合格。L2 断言=①四项齐判 PASS、②缺「下一步」判 FAIL。
- **L69 状态完整性断言**：L0 恢复现场后先点数：该在的东西都在吗？对话、变量、中间结果，缺一样就别急着跑。L1 恢复后对照执行前快照逐项断言（键集合+值类型），输出缺失清单。L2 断言=①缺键报缺、②全齐报 PASS。
- **L70 恢复成本估计**：L0 断点不是免费的：它算一算"从存档接着干"要重新付多少（重读文件、重建上下文），再决定值不值得断。L1 估计重算 token/时间 vs 存档大小，给「断/不断」建议。L2 断言=①重算成本>存档收益时建议不断、②反之建议断。
- **L71 断点新鲜度**：L0 存档放久了会过期：代码改了、依赖换了，老存档接着用会翻车。L1 对 checkpoint 记录环境指纹（依赖版本/文件哈希），恢复时比对，不一致 → 先升级存档再恢复。L2 断言=①指纹不一致拦截、②一致放行。

## c19 代理间交接（3 件）— 证据：`agent handoff protocol` 236 仓半满（协议层 vs v1 L33 内容层，正交）

- **L72 交接协议完整性**：L0 一个伙伴把活交给另一个时，交接单必须写全：干到哪、卡在哪、下一步谁干。缺项的交接单不许收。L1 校验交接包必填字段（状态/阻塞/下一步/权限边界），缺项拒收并列缺失。L2 断言=①缺「阻塞项」拒收、②齐全签收。
- **L73 注意力分诊**：L0 多个伙伴同时干活时，它回答一个问题：现在谁在等我？谁的事最急？L1 汇总各协作者状态（working/waiting/done），按等待时长+阻塞链长度排优先级。L2 断言=①被阻塞链最长的排最前、②done 的不占队列。
- **L74 并发写冲突闸**：L0 两个人同时改同一份文件，后写的会盖掉先写的——它把这单查出来，让你决定谁先。L1 检测多 agent 对同一资源的写意图重叠（资源路径+时间窗），重叠 → 冲突报告。L2 断言=①同资源双写意图报冲突、②不同资源放行。

## c20 评审器健康（4 件）— 证据：`eval drift` 对口仓 star 全 ≤3；`confidence calibration` 偏学术、工程原语缺位；neuron-explorer：结论必须对 256 随机对照做百分位排名

- **L75 评审器漂移门**：L0 打分的人自己也会"越打越松"或"越打越严"——它盯着评审分数的分布，变了就提醒：先校准再信。L1 对评审分数序列做分布检验（均值漂移/方差膨胀），超阈判评审器漂移，暂停采信。L2 断言=①分数整体上移 2σ 报漂移、②平稳不报。
- **L76 双评审分歧**：L0 让两位评审看同一份东西，分歧太大说明标准不清或有人在瞎打——先解决分歧，再谈分数。L1 双评审分差>阈 → 输出分歧定位（逐维度）+ 强制第三次仲裁。L2 断言=①分差超阈触发仲裁、②一致直接过。
- **L77 随机对照显著性**：L0 你说"我这个方法有效"？先跟瞎蒙的对照组比：跑 N 次随机基线，你的成绩得明显好过它们才算数。L1 对自评结论生成 N 个随机基线（打乱/占位/反向），算目标成绩的百分位，<95 位 → 不显著。L2 断言=①真提升判显著、②随机水平判不显著。
- **L78 校准体检**：L0 一个人总说"90% 有把握"但十次错三次，那他的 90% 不值 90%——它核对"说的把握"和"真对的比例"差多远。L1 收集（自报置信，实际对错）对，算校准误差（ECE 简化版），超阈出校准系数。L2 断言=①高置信低正确率报过信、②校准良好不报。

## c21 提示词回归（3 件）— 证据：`prompt regression testing` 487 仓但对口全是 star≤17 早期件

- **L79 快照回归**：L0 改提示词前先给老提示词拍快照、存下它的典型回答；改完后重跑同样的问题，答案变了就亮灯。L1 维护（输入→期望特征）快照集，改版后重放比对特征（不比对字面），漂移列出。L2 断言=①关键特征漂移报回归、②一致放行。
- **L80 行为漂移门**：L0 提示词没改，模型行为也可能悄悄变——它定期用固定题库抽查，变了就查原因。L1 固定探针题库周期重跑，输出行为指纹哈希序列，哈希变化 → 漂移警报。L2 断言=①指纹变化报警、②稳定不报。
- **L81 规则引用判定**：L0 审查结论必须指出"违反了哪一条规定、原文是什么"，说不出条目的结论不算数。L1 校验每条结论含（规则 ID+原文引用+修复建议）三件套，缺一判无效。L2 断言=①缺原文引用判无效、②三件套齐判有效。

## c22 上下文经济学（3 件）— 证据：HN 实战痛点：中部剪枝作废前缀缓存（所有人都想做、都因此放弃）；上下文太多太少都坏；相关信息散落各处

- **L82 缓存感知剪枝**：L0 删上下文不是免费的：删中间一段，后面全部要重算。它先算"删了省的钱 vs 重算赔的钱"，划算才删。L1 输入剪枝方案（位置/长度），估算缓存重算成本 vs token 节省，负收益 → 否决或改尾部删。L2 断言=①中部删除负收益被否、②尾部删除正收益放行。
- **L83 双阈值充足度**：L0 上下文不是越多越好，太少也傻——它给"信息够不够"设上下两条线，越线都报警。L1 量化当前上下文的关键信息覆盖度，双阈值判定：溢出 → 压缩，不足 → 补料。L2 断言=①超上阈报压缩、②低于下阈报补料。
- **L84 相关性邻接度**：L0 相关的信息要放在一起：答案的一半在开头、一半在结尾，中间隔一万字，模型容易顾头不顾尾。L1 量化相关信息在上下文中的分散度（关键块间距/总长），超阈建议**重组**而非压缩。L2 断言=①高分散建议重组、②集中不报。

## c23 记忆写入闸（3 件）— 证据：`agent memory decay` 半满但产品化临近（需差异化）；HN 多人独立指出：旧记忆不删只覆盖、模型随手挑最近的，是最先坏掉的环节

- **L85 矛盾裁决门**：L0 新记忆和旧记忆打架时，不许"都留着看模型心情"——写入前必须裁决：留哪个、为什么。L1 写入前与既有记忆比对，发现矛盾对 → 强制显式裁决（覆盖/并存/丢弃+理由），未裁决拒写。L2 断言=①矛盾未裁决拒绝写入、②裁决后写入并记录理由。
- **L86 信用衰减回摊**：L0 记忆也讲"保鲜期"：三年前的评价和昨天的评价分量不该一样。它给每条记忆按来源信用和时间打折扣。L1 记忆检索时按（来源信用 × 时间衰减）排序加权，低分记忆降权不删除。L2 断言=①旧低信记忆排后、②高信新记忆排前。
- **L87 跨会话陈旧引用**：L0 新会话里引用"上次说的那个文件"——那个文件可能早删了。它在新会话开始时把这类引用全部翻出来验一遍。L1 扫描开场上下文中的历史引用（路径/URL/人名任务），逐一验证存在性，失效列清单。L2 断言=①失效引用报警、②有效不报。**v1.1 边界（日跑实测反馈）**：路径只认 ASCII 段且末段带扩展名（行内记法 /x/y 不是路径）；URL 离线不可验证时单列 unverified、不谎称失效（strict 才报警）。

## c24 事前准入（3 件）— 证据：day-trader-skill 一周 1789 星的核心直觉：止损/目标必须进场前定好，否则不许进场

- **L88 退出判据先行**：L0 出发的车必须先说好在哪停：没有"怎样算失败"的任务不许开跑。L1 任务启动前校验含（成功判据+失败判据+时限）三元组，缺失败判据 → 拒绝开始。L2 断言=①缺失败判据拒启、②三元组齐放行。
- **L89 重放预演**：L0 大动作之前，先拿历史数据"彩排"几遍可能的结局，看最坏的那种能不能接受。L1 用历史轨迹重放 N 个变体，输出结局分布与最坏情况，最坏超承受线 → 建议不做或改方案。L2 断言=①最坏超线建议不做、②分布可接受放行。
- **L90 廉价试错阶梯**：L0 试错要从最便宜的试起：先查文档（免费），再跑小样（几毛钱），最后才上全量（真金白银）。顺序反了要拦。L1 校验试错序列的成本单调性，发现"先贵后便宜" → 拦截并建议重排。L2 断言=①全量先行拦截、②阶梯正确放行。

## c25 修复伴随件（3 件）— 证据：php2shell 系列把「漏洞+检测规则」成对发布；BeautifulRust：移植必须先搬测试

- **L91 检测件伴随**：L0 修好一个 bug，必须同时交"下次怎么提前发现它"的哨兵。只修不设哨，等于等着它再犯。L1 校验修复产物包含配套检测件（断言/规则/监控项），缺失 → 修复不算完成。L2 断言=①无检测件判未完成、②有检测件放行。
- **L92 移植等价性**：L0 把代码搬到新地方，先搬老测试：老测试全过，才叫"搬好了"，不叫"重写了一份像的"。L1 移植前校验测试套件已迁移且通过率达标，未达标判「移植未完成」。L2 断言=①测试未迁移拦截、②迁移且通过放行。
- **L93 跨实现等价**：L0 同一个功能有两份实现时，拿同样的输入喂两份，答案必须一致；不一致就说明有一份是错的。L1 固定输入集跑双实现，diff 输出，不一致定位首个分歧点。L2 断言=①分歧点被定位、②一致判 PASS。

## c26 撤销与破坏面（3 件）— 证据：v1 L39 只查"回滚就绪"（有没有快照），本簇查"撤销路径唯一且实测过"；配额余量闸源自 harp

- **L94 撤销唯一性实测**：L0 危险按钮旁边必须有且只有一个"撤销"按钮，而且这个撤销按钮**必须真按过一次、真的管用**。L1 破坏性操作前校验：撤销路径存在且唯一，且撤销路径本身被实际演练过（有演练记录）。L2 断言=①撤销未演练拦截、②已演练放行。
- **L95 配额余量闸**：L0 开新任务前看一眼钱包和油表：本月额度还剩多少？这单要烧多少？不够就别开。L1 读配额日志（时间窗用量+上限），预算新任务消耗，余量不足 → 拒开或降档。L2 断言=①余量不足拒开、②充足放行。
- **L96 昂贵步骤前置审计**：L0 花大钱的那一步之前，必须有一次专门的"过堂"：这一步真的必要吗？有没有更省的走法？L1 识别标记为昂贵的步骤，前置强制审计（必要性+替代方案两字段），缺审计不放行。L2 断言=①缺替代方案字段拦截、②齐全放行。

## c27 确定性分工（3 件）— 证据：HN（State of Context Engineering 讨论）：每步都该问"这该进代码还是该给模型"

- **L97 可确定化检测**：L0 有些活 agent 干了一百遍、每次都一样、从不出错——这种活就不该再麻烦模型了，写成死代码又快又稳。L1 统计步骤的历史执行（输入模式固定+输出恒定+零失败），连续 N 次满足 → 建议**确定化**。L2 断言=①100 次恒定建议固化、②输出有变化不建议。
- **L98 分工账本**：L0 家里记账要分"谁花的"：这里记每一步是代码干的还是模型干的、花了多少，月底一看就知道钱去哪了。L1 按步骤记录执行者类型（code/model）+成本，聚合输出分工成本比与趋势。L2 断言=①账本能按类型汇总、②缺类型标记的步骤被列出。
- **L99 确定性复验**：L0 号称"每次都一样"的代码，连跑两次必须一字不差；差一个字，就别叫确定。L1 对标记为确定性的步骤连跑 2 次，输出逐字节比对，不一致 → 撤销确定性标记。L2 断言=①两次不一致摘标记、②一致保留。

## c28 认知诚实（4 件）— 证据：内部资产原语化（an internal five-gate judge module 十项自检）；an anti-sycophancy protocol L4 异议四件套

- **L100 无源数字拦截**：L0 报告里每个数字都要能答上"哪来的"；答不上来的数字，进不了对外的门。L1 扫描文本中的数字断言，逐个要求来源字段（文件/命令/URL），缺来源 → 拦截该数字。L2 断言=①无源数字被拦、②有源数字放行。
- **L101 绝对化红灯**：L0 "全部成功、完美无缺、一次通过"——这种话一出就先扣分：世界上没有这么顺的事，说这么满多半是没认真查。L1 检测绝对化词表命中，命中即封顶评分（cap 0.6）并要求改写为具体数字。L2 断言=①「全部成功」触发封顶、②「55/55 可跑」不触发。
- **L102 负对照强制**：L0 好尺子要先证明"它能拦住废话"，才能拿来量真话：每个验收标准必须配一个"故意做错"的反例并确认真能拦住。L1 校验验收标准附带负对照记录（反例+拦截结果），缺失 → 判据本身不合格。L2 断言=①无负对照判据降级、②有负对照且拦截成功判据有效。
- **L103 可证伪化**：L0 一个靠谱的结论要能回答："什么样的证据出现，我就承认我错了？"答不上来的结论只是口号。L1 校验结论附带可证伪条件（什么观察会推翻它），缺失 → 降级为「假说」而非「结论」。L2 断言=①无可伪条件降级、②有则保留结论级。

## c29 工具语义（4 件）— 证据：`tool call` 生态集中在框架层，语义判定件缺位；v1 L55 是"工具自测"（功能对不对），本簇是"语义清不清"

- **L104 契约漂移检测**：L0 工具的说明书会悄悄变：参数改名、返回多字段。它定期对着真工具核对说明书，变了就喊。L1 缓存工具 schema 指纹，调用前比对，漂移 → 列差异并标记受影响调用点。L2 断言=①schema 变化被列出、②一致放行。
- **L105 超时语义**：L0 调用超时后有两种可能：它停了（可以重试）或它还在跑（重试会重复干活）。分不清就重试，是事故之源。L1 为每类调用标注超时语义（cancellable/uncancellable），不可取消类超时后禁止盲重试。L2 断言=①不可取消类拦截盲重试、②可取消类允许。
- **L106 结果新鲜度**：L0 工具返回的数据要贴"何时采的"标签：三秒前的股价能用，三天前的不能用。L1 为工具结果打时间戳，消费方校验年龄 vs 该数据类型的保鲜期，过期拒用。L2 断言=①过期数据拒用、②新鲜放行。
- **L107 重试退避策略**：L0 失败了别立刻疯狂重试——那样只会把对方打得更死。等一等、越等越久，才是礼貌的试法。L1 校验重试序列满足指数退避+上限（无连续零间隔、总次数封顶），违规拦截。L2 断言=①零间隔连击拦截、②合规退避放行。

## c30 依赖与环境（3 件）— 证据：恢复类事故的隐藏根因：环境悄悄变了（依赖/版本/路径/密钥面）

- **L108 依赖漂移警报**：L0 上周能跑的程序这周跑不动，十有八九是环境里某个东西被人换了。它每周给依赖拍快照，一比对就知道谁变了。L1 记录依赖清单哈希，定期比对，差异 → 列出增/删/改并评估影响面。L2 断言=①版本变更被列出、②无变化不报。
- **L109 环境指纹对比**：L0 恢复现场前先核对"这是不是当初那个房间"：路径、系统、版本，不对就别硬跑。L1 恢复/复用前采集环境指纹与存档指纹比对，不一致 → 要求确认或重建。L2 断言=①指纹不符要求确认、②一致直接恢复。
- **L110 对外敏感面扫描**：L0 把东西拿出去给人看之前，最后扫一遍：密钥、真实姓名、内部路径，一样都不能带走。L1 对待发布产物扫描敏感词表（凭据/真名/内部路径/内部规则名），命中即拦并列位置。L2 断言=①含密钥样串拦截、②干净产物放行。
